# Production daemon with dashboard, process supervision, and host routing

This change transforms `doot --prod` from a stub into a full production daemon: a dashboard web UI on port 8080 for managing deployed apps, a host-header reverse proxy on port 80, per-app child process supervision with exponential backoff, GitHub clone/pull integration, env var validation, cgroups v2 isolation, and systemd service file generation. The architecture is a single-binary multi-service design where one async event loop drives both the dashboard and the proxy router, with supervised child processes managed via `osproc`. Password is generated on first run, hashed with argon2id, and the system is idempotent on subsequent invocations.

Watch for: PAT stored in plaintext in SQLite (confirmed), session expiry is checked but never enforced (confirmed), `findRoute` returns a raw pointer into a seq that can dangle if the seq is modified concurrently (confirmed), and the global `nim.cfg` now links argon2/ssl/crypto into every compilation target including unrelated ones (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The daemon entry point (`runProd`) handles first-run initialization (password generation, systemd registration, config persistence) and subsequent-run status display, then creates three components — dashboard, router, supervisor — and enters `runForever`. Signal handling stops children gracefully via `ptr` globals for the signal hook, which is inherently fragile if the stack-allocated supervisor is moved.

The dashboard implements a standard cookie-session flow with 16 CRUD routes, all server-rendered HTML. Session validation queries the DB for the session ID but never compares the stored `expires_at` timestamp, meaning sessions live forever until explicitly deleted — a functional gap in the auth layer.

GitHub PATs are stored as plaintext strings in the SQLite `dootd_apps` table alongside app config. For a production daemon managing deployments on a VPS, this is a meaningful credential exposure surface — anyone with read access to the DB file gets repository write access. PATs also leak into git command output stored in the logs table.

The host-header router uses `findRoute` which returns `unsafeAddr` into a `seq[ProxyRoute]`. Since routes can be added/removed via the dashboard while the router is serving requests (same async event loop, different callbacks), a seq reallocation during `addRoute` would invalidate the pointer before the response handler uses it.

The process supervisor computes exponential backoff (capped at 30s, error state after 5 crashes in 60s) but `restartChild` calls `sleep(min(backoffMs, 100))` — a synchronous call that blocks the entire async event loop and also means computed backoffs above 100ms are never honored.

The `nim.cfg` change adds `--passL:"-largon2"`, `--passL:"-lssl"`, `--passL:"-lcrypto"` globally, meaning all targets (including test files that don't need crypto) now link against these libraries. This creates a hard build dependency for every module in the project.

<details>
<summary>Issues (7)</summary>

1. **PAT stored in plaintext** — GitHub Personal Access Tokens are stored unencrypted in the SQLite `dootd_apps.pat` column. Encrypt at rest or use a separate secrets store.
2. **Session expiry never enforced** — `validateSession` queries `expires_at` but returns `true` without comparing it to the current time. Sessions never expire.
3. **Dangling pointer in findRoute** — Returns `unsafeAddr` into a `seq` that can be reallocated by concurrent `addRoute`/`removeRoute` calls in the same event loop. Return a value copy instead.
4. **Synchronous sleep blocks event loop** — `restartChild` calls `sleep(min(backoffMs, 100))` which blocks the entire async loop. Use `sleepAsync` or defer restart via a timer callback.
5. **Global nim.cfg links argon2/ssl/crypto for all targets** — Every compilation now requires libargon2, libssl, and libcrypto even if the module doesn't use them. Use per-module pragmas or conditional flags.
6. **No CSRF protection on POST routes** — All state-mutating dashboard routes accept bare POST requests with no token verification. Any page the admin visits could submit forms to the dashboard.
7. **CPU usage metric is misleading** — `getCpuUsage` computes cumulative CPU time ratio from boot, not current instantaneous load. The percentage will always be high on active systems regardless of current load.

## PAT and credential storage

The `dootd_apps` table stores the PAT as a plaintext column:

```sql
pat TEXT NOT NULL DEFAULT ''
```

`sanitizeGitUrl` embeds it directly into the clone URL (`https://<pat>@github.com/user/repo.git`). Since the DB file lives at `~/.dootd/dootd.db` with user permissions, any process running as the same user (or any backup that includes the file) exposes all configured PATs. The git command output (which may contain the PAT in error messages) is returned in `GitResult.output` and stored in the app logs table via `addAppLog`.

The dashboard's `renderAppForm` renders the PAT into an `<input type="password" value="` & app.pat & `">` field — present in the HTML source on the edit page. Combined with the lack of CSRF protection, a cross-site form submission could exfiltrate the value.

## Session expiry gap

`createSession` stores a computed `expires_at` timestamp:

```nim
let expires = $(now() + initDuration(hours = SessionExpireHours))
```

But `validateSession` only checks whether the row exists:

```nim
proc validateSession*(db: DbConn, sessionId: string): bool =
  ...
  let row = db.getRow(...)
  if row[0].len == 0:
    return false
  # Session exists - consider it valid (simple expiry check)
  result = true
```

The comment says "simple expiry check" but no check happens. Sessions persist until the user logs out or the DB is wiped.

## Pointer unsafety in the router

```nim
proc findRoute*(router: HostRouter, hostname: string): ptr ProxyRoute =
  for i in 0..<router.routes.len:
    if router.routes[i].hostname.toLowerAscii() == cleanHost:
      return unsafeAddr router.routes[i]
  return nil
```

If `addRoute` appends and triggers a seq reallocation between `findRoute` returning and `forwardRequest` reading the port from the pointer, the pointer is invalid. The window requires an `await` between finding and using the route — which does happen in `startRouter`'s callback where `forwardRequest` is awaited after the `findRoute` call.

## Blocking sleep in supervisor restart

```nim
proc restartChild*(supervisor: var ProcessSupervisor, appId: int64): bool =
  ...
  if child.backoffMs > 0:
    sleep(min(child.backoffMs, 100))  # Cap actual sleep for responsiveness
```

The cap at 100ms means the exponential backoff computation (up to 30 seconds) is never applied. The process always waits at most 100ms before restarting, and that 100ms blocks the entire async event loop.

## CPU stat misrepresentation

`getCpuUsage` reads `/proc/stat` once and computes `(total - idle) / total * 100`. These are cumulative counters since boot — the result represents average utilization since system start, not current load. To get instantaneous usage, the code needs to sample twice with a short interval and compute the delta. The dashboard will show a stable ~20-40% regardless of actual current activity.

## Test coverage gaps

Not tested: the actual async behavior of `startDashboard`/`startRouter` under concurrent load, the `forwardRequest` proxy path (would require a live HTTP server), signal handler behavior, the interaction between `checkChildren` polling and restart scheduling in a running event loop, and CSRF attack vectors.
