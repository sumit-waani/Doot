# Production daemon v3: all v2 issues resolved

This is the third and final review pass. The four issues raised in v2 have all been addressed. CPU stats now read `/proc/loadavg` with no blocking calls. All user-controlled strings are escaped via `escapeHtml()` before HTML interpolation. The session expiry fallback returns `false` on unparseable timestamps (fail-closed). `stopChild` uses `waitForExit(timeout)` instead of a sleep-polling loop.

Watch for: nothing blocking. The remaining architectural notes (PAT plaintext storage, `waitForExit` still being synchronous in `stopChild`) are documented as known v1 trade-offs with TODO comments and are not regressions.

**Verdict**: APPROVED

## High-level view

CPU stats read `/proc/loadavg` in a single non-blocking `readFile` — no delta sampling, no sleep. The trade-off is slightly less precise instantaneous measurement vs. two `/proc/stat` reads, but zero blocking is the correct priority for a request handler.

HTML escaping covers all user-controlled interpolation points: app names, hostnames, log messages, env vars, form error messages, and search filters. The stored XSS vector from v2 is eliminated.

Session validation returns `false` on unparseable `expires_at` timestamps. Fail-closed.

`stopChild` uses `waitForExit(timeout)` instead of a sleep-poll loop. It still blocks for up to 5s during admin-initiated stop/redeploy — acknowledged in a TODO for v2 async improvement. Acceptable for v1 since it's not on the hot path.

## Resolution verification

All four v2 issues confirmed fixed by code inspection:

**CPU stats (dootd_stats.nim:34-58)** — `getCpuUsage()` reads `/proc/loadavg` once, parses the 1-minute load average, counts CPUs from `/proc/stat` line headers, and returns `(load1 / cpuCount) * 100`. No `sleep` import, no blocking call.

**HTML escaping (dootd_html.nim:8-17)** — `escapeHtml` replaces `&` → `&amp;`, `<` → `&lt;`, `>` → `&gt;`, `"` → `&quot;`. All render procs use it: `renderAppList`, `renderAppDetail`, `renderLogsPage`, `renderAppForm`, `renderLayout`, `renderLoginPage`, and `renderSettingsPage`.

**Session expiry (dootd_dashboard.nim:56-68)** — The fallback path:
```nim
except TimeParseError:
  # If we still cannot parse, reject the session (fail-closed)
  return false
```

**stopChild (dootd_process.nim:108-127)** — Single `waitForExit(timeout = timeoutMs)` call replaces the prior `sleep(100)` polling loop. Escalation to `kill()` + secondary `waitForExit(timeout = 1000)` handles the stubborn-process case.
