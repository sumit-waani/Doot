# HTTP runtime for the Doot DSL: routing, context, static serving, and server (v2)

This is a second-pass review after the five issues from v1 were addressed. The path traversal guard now uses `absolutePath` with a prefix check, session IDs use `std/sysrand.urandom`, and the three intentional Phase 3 limitations (auth no-op, multipart absent, session cookie unwired) are documented with prominent comments explaining the phased delivery. All 373 tests pass.

Watch for: the `absolutePath` path traversal fix relies on CWD-relative resolution rather than symlink-resolved canonicalization — functional against `..` attacks but does not guard against symlinks within the static directory (possible, low severity). No other blocking issues remain.

**Verdict**: APPROVED

## High-level view

The path traversal fix resolves `..` attacks correctly. The remaining gap is symlinks: a symlink placed inside `static/` pointing to an external path would pass the prefix check since `absolutePath` does not follow symlinks. This requires write access to the static directory, making it a defense-in-depth concern rather than a real attack surface in Doot's deployment model.

## Path traversal fix: symlink gap

The v1 review flagged that `.replace("..", "")` was bypassable. The fix at `static_files.nim:48–54`:

```nim
let staticRoot = absolutePath(basePath)
let candidate = absolutePath(basePath / requestPath.strip(chars = {'/'}))
if not candidate.startsWith(staticRoot):
  return errorResponse(404, "File not found")
```

Nim's `absolutePath` expands relative paths against the current working directory and resolves `..` segments in the process. Testing confirms: `absolutePath("static/../../../etc/passwd")` yields `/projects/etc/passwd`, which fails the `startsWith("/projects/sandbox/Doot/static")` check. The `strip(chars = {'/'})` prevents the request path from being treated as absolute by Nim's `/` operator (which would otherwise ignore the left operand).

The remaining gap: `absolutePath` does not follow symlinks. If an attacker can place a symlink at `static/evil -> /etc/passwd`, the resolved path would be `/projects/sandbox/Doot/static/evil`, passing the prefix check while serving `/etc/passwd`. Since the static directory is populated by the developer (not by users), this is not an exploitable vector in normal Doot usage. If future phases allow user-uploaded static content, switching to `expandFilename` (resolves symlinks) would close this gap.
