# HTTP runtime for the Doot DSL: routing, context, static serving, and server

This change adds the HTTP serving layer for the Doot compiler — ten new modules that take parsed `.do` routes and execute them as a running server. The approach uses `std/asynchttpserver` (stdlib fallback since the mummy library was unreachable) with a segment-based route matcher, a `DootCtx` request context object, and a pipeline for CORS, error pages, session stubs, static files, and an embedded HTMX shim. Template rendering is deliberately stubbed (Phase 4).

Watch for: path traversal mitigation in static file serving is bypassable (confirmed), auth enforcement is entirely a no-op — routes marked `auth: required` are accessible without any check (confirmed), and session IDs use `std/random` without cryptographic seeding (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

Route matching works by splitting paths on `/`, sorting registered routes so static segments outrank parameterized ones, and iterating linearly. The scoring system (static = +1000, segment count × 10, static segments × 5) gives deterministic priority without requiring the caller to order registrations correctly.

The request context is assembled per-request from the URL, headers, form body, and path params extracted by the router. There is no multipart form parsing — file uploads will silently produce an empty `file` table. Session and currentUser fields are initialized but never populated from request data by the server pipeline.

Static file serving and the embedded HTMX endpoint bypass the route table entirely, matching by path prefix in the request handler. Both apply gzip via a direct zlib C FFI wrapper. The path traversal guard on static files strips `..` substrings but does not normalize the path, leaving several bypass vectors open.

CORS is deny-by-default: any request carrying an `Origin` header is rejected with 403 unless the config's `allowedOrigins` is populated. The auth check is a placeholder `discard` — the DSL's `auth: required` semantic has no runtime enforcement in this phase.

The session store schema and CRUD are implemented against SQLite with upsert semantics, but the server never reads session cookies from incoming requests or writes Set-Cookie on outgoing responses. Session integration is wiring-ready but inactive.

Testing covers 114 new tests across three files, including a real threaded server exercised by `std/httpclient`. The E2E suite uses `sleep(500)` for server readiness rather than a probe, which could flake on slow CI. Not tested: multipart form uploads, session cookie round-trips, concurrent requests, and the path traversal bypass vector.

<details>
<summary>Issues (5)</summary>

1. **Path traversal bypass in static file serving** — Stripping `..` substrings is insufficient; encoded traversals like `%2e%2e` or sequences like `....//` survive the filter. Resolve the path with `os.absolutePath` and verify it starts with the static root.
2. **Auth enforcement is a no-op** — Routes with `authRequired = true` execute their handler unconditionally. If this is intentional for Phase 3, document it with a loud log/comment; if not, return 401 when no valid session exists.
3. **Session ID uses non-cryptographic randomness** — `initRand()` with no seed argument uses a time-based default. Use `/dev/urandom` or `std/sysrand.urandom` for session IDs.
4. **Multipart form parsing absent** — `ctx.form` is only populated for `application/x-www-form-urlencoded`; file uploads or multipart posts produce an empty context. The `UploadedFile` type exists but is never instantiated.
5. **Session cookie never read or written** — The server pipeline does not extract a session ID from request cookies or send `Set-Cookie` headers. The session store is inert until Phase 5 or until this wiring is added.

## Path traversal bypass in static file serving

The guard at `static_files.nim:49` is:

```nim
let normalized = requestPath.replace("..", "")
```

This removes literal `..` substrings, but the input has already been URL-decoded by the HTTP layer. A request for `/static/%2e%2e/%2e%2e/etc/passwd` passes through because the decoded path `../../etc/passwd` is never seen by this logic — depending on whether `asynchttpserver` decodes paths before or after handing them to the callback. Even without encoding, `....//` collapses to `../` after one pass of `.replace`. The correct approach is to join with `basePath / ...`, then call `absolutePath` on the result and assert it starts with `absolutePath(basePath)`.

## Auth enforcement is entirely stubbed

In `server.nim:113–117`:

```nim
if routeMatch.route.authRequired:
  # In Phase 3, auth is a stub. Check if there's a session cookie.
  # For now, routes marked auth: required will be accessible but flagged.
  discard
```

Every route that declares `auth: required` (the default) runs its handler without restriction. The semantics are fail-open: any route without an explicit `auth: none` is nominally protected but actually unguarded. Given that Phase 5 is the auth implementation this may be intentional, but the gap should be documented more visibly than an inline comment — at minimum a startup warning log.

## Session ID generation with std/random

`session.nim:32`:

```nim
var r = initRand()
```

`initRand()` without arguments seeds from the system clock. Two sessions created within the same millisecond could receive the same ID. More critically, the PRNG state is predictable with knowledge of the creation time. For a session ID that gates access to user data, `std/sysrand.urandom(16)` (available in Nim 2.x) provides cryptographically secure bytes. Since cookie signing is explicitly deferred to Phase 5, the session ID is the only defense against session hijacking in the interim.

## CORS and CSRF boundary

The "no Origin = same-origin" assumption at `cors.nim:83` is correct for CORS enforcement but does not constitute CSRF protection. The framework doesn't yet have CSRF token support — forms submitted from the same origin will bypass CORS checks and reach handlers without any anti-forgery validation.

## Test coverage gaps

The E2E suite spawns a threaded server on port 18932 and uses a hardcoded `sleep(500)` to wait for readiness rather than a retry/probe, which could flake on slow CI. Not tested: multipart form uploads, session cookie round-trips, concurrent requests under load, and the path traversal bypass vector.
