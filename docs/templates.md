# Templates

Doot uses a Pug-style, whitespace-significant template syntax combined with Jinja-style inheritance (`extends`, named `block`s, partials). Templates live in the `views/` directory and use the `.do` file extension.

---

## Core Syntax

### Indentation-Based Nesting

Templates use indentation (spaces) to determine element nesting. There are no closing tags.

```
div
  h1 "Hello"
  p "Welcome to the app"
```

Produces:

```html
<div>
  <h1>Hello</h1>
  <p>Welcome to the app</p>
</div>
```

Indentation level determines parent-child relationships. A child element is indented one level deeper than its parent. Dedenting closes the parent element implicitly.

### Elements

Bare words at the start of a line are HTML tag names:

```
div
h1
p
a
form
input
button
nav
main
footer
section
article
span
ul
li
```

### Text Content

Text is specified as a string literal after the tag:

```
h1 "All Posts"
p "No posts yet."
button "Submit"
```

Produces:

```html
<h1>All Posts</h1>
<p>No posts yet.</p>
<button>Submit</button>
```

### String Interpolation in Text

Use `#{}` for dynamic content inside text strings:

```
h1 "Hello, #{user.email}"
p "You have #{posts.count} posts"
a href="/posts/#{post.id}" "Read more"
```

## Expression Output

### Escaped Output (`=`)

The `=` prefix outputs an expression value, auto-escaped by default:

```
h1= post.title
p= post.body.truncate(100)
span= user.email
```

Produces (with auto-escaping):

```html
<h1>My &lt;b&gt;Post&lt;/b&gt;</h1>
```

Auto-escaping prevents XSS attacks. Any HTML special characters in the expression value are escaped before output. This is Rule 4 in action: secure by default.

### Using `=` Within a Line

The `=` can appear directly after a tag name (no space needed between tag and `=`):

```
p= post.body
h2= post.title
span= format_date(post.created_at)
```

### Raw Output (Opt-In)

To output unescaped HTML (when you know the content is safe), use `!=`:

```
div!= post.rendered_html
```

This bypasses auto-escaping. Use with caution. Only appropriate when the content has already been sanitized or is generated by trusted code.

## Attributes

Attributes are written as key-value pairs after the tag name:

```
a href="/posts" "All Posts"
input type="text" name="title" placeholder="Post title" required=""
form method="post" action="/posts"
link rel="stylesheet" href="/app.css"
img src="/images/logo.png" alt="Logo"
```

Produces:

```html
<a href="/posts">All Posts</a>
<input type="text" name="title" placeholder="Post title" required="">
<form method="post" action="/posts">
<link rel="stylesheet" href="/app.css">
<img src="/images/logo.png" alt="Logo">
```

### String Interpolation in Attributes

Dynamic values in attributes use `#{}`:

```
a href="/posts/#{post.id}" = post.title
form method="post" action="/posts/#{post.id}/comments"
img src="/uploads/#{post.cover_path}" alt="#{post.title}"
```

### Boolean Attributes

For boolean HTML attributes, use an empty string value:

```
input type="checkbox" checked=""
input type="text" disabled=""
button type="submit" disabled=""
```

## Class Shorthand

Use `.` notation to add CSS classes (Pug-style):

```
div.post-card
  h2.post-title= post.title
  p.post-excerpt= post.body.truncate(100)
```

Produces:

```html
<div class="post-card">
  <h2 class="post-title">...</h2>
  <p class="post-excerpt">...</p>
</div>
```

### Multiple Classes

Chain multiple classes with dots:

```
div.card.shadow.rounded
  p.text-sm.text-gray "Small gray text"
```

Produces:

```html
<div class="card shadow rounded">
  <p class="text-sm text-gray">Small gray text</p>
</div>
```

---

## ID Shorthand

Use `#` notation to set an element's ID:

```
div#main-content
  h1#page-title "Welcome"
```

Produces:

```html
<div id="main-content">
  <h1 id="page-title">Welcome</h1>
</div>
```

### Combined Class and ID

Classes and IDs can be combined on the same element:

```
div#sidebar.panel.dark
  nav#main-nav.vertical
```

Produces:

```html
<div id="sidebar" class="panel dark">
  <nav id="main-nav" class="vertical">
```

## Template Inheritance

### `extends`

A template can extend a layout. The layout defines named blocks that the child template fills:

```
# views/posts/index.do
extends "layouts/base"

block title
  "All Posts"

block content
  h1 "All Posts"
  each post in posts
    div.post-card
      h2= post.title
```

The `extends` directive must be the first line of the template. The path is relative to `views/`.

### Multiple Named Blocks

Layouts define multiple named blocks, not just a single `content` block. This is a deliberate design decision: even basic web pages need control over the `<title>`, `<head>` contents, and body content at minimum.

```
# views/layouts/base.do
doctype html
html
  head
    title= block title || "Doot App"
    block head
    style-embed "app.css"
  body
    nav
      a href="/" "Home"
      if ctx.current_user
        a href="/logout" "Logout"
      else
        a href="/login" "Login"
    main
      block content
    footer
      p "Built with Doot"
```

A child template fills any combination of these blocks:

```
# views/posts/show.do
extends "layouts/base"

block title
  = post.title

block head
  meta name="description" content="#{post.body.truncate(160)}"

block content
  article
    h1= post.title
    div.post-body= post.body
    p.meta "Published #{format_date(post.created_at)}"
```

### Default Block Values

A block can have a default value using `||`:

```
title= block title || "Doot App"
```

If the child template does not define a `block title`, the default "Doot App" is used. If the child provides content, the default is overridden.

## Partials

Partials are reusable template fragments. They are included using the `partial` keyword:

```
partial "comments/form", post: post
partial "partials/nav"
partial "posts/card", post: post, show_author: true
```

### Partial Syntax

```
partial "path", key1: value1, key2: value2
```

- Path is relative to `views/` (e.g., `"comments/form"` resolves to `views/comments/_form.do` or `views/comments/form.do`)
- Key-value pairs are the locals available inside the partial
- Only explicitly passed locals are accessible (same as `render`: no implicit variable leakage)

### Partial File Example

```
# views/comments/_form.do
form method="post" action="/posts/#{post.id}/comments"
  textarea name="body" placeholder="Write a comment..." required=""
  button type="submit" "Post Comment"
```

Used from a page template:

```
# views/posts/show.do
extends "layouts/base"

block content
  h1= post.title
  div.post-body= post.body

  h2 "Comments"
  each comment in comments
    div.comment
      p= comment.body
      span.meta "by #{comment.user_id}"

  partial "comments/form", post: post
```

## Control Flow

### `if` / `else`

Conditional rendering in templates:

```
if ctx.current_user
  a href="/logout" "Logout"
else
  a href="/login" "Login"
```

```
if posts.empty?
  p "No posts yet."
else
  each post in posts
    div.post-card
      h2= post.title
```

`if` blocks use indentation to determine their scope (no `end` keyword needed in templates because indentation is structural).

### `each`

Iterate over a collection:

```
each post in posts
  div.post-card
    h2
      a href="/posts/#{post.id}" = post.title
    p= post.body.truncate(100)
    span.date= format_date(post.created_at)
```

```
ul
  each item in items
    li= item.name
```

The loop variable (e.g., `post`, `item`) is scoped to the `each` block.

## Accessing Locals

Templates receive data via the explicit locals passed in `render` calls from handlers:

```
# In the handler:
render "posts/index", posts: posts, page_title: "All Posts"
```

```
# In the template (views/posts/index.do):
extends "layouts/base"

block title
  = page_title

block content
  h1= page_title
  each post in posts
    div.post-card
      h2= post.title
```

Only the named locals (`posts` and `page_title` in this example) are available in the template. There is no implicit access to handler variables or global state beyond `ctx.current_user` (which is always available in templates for auth-related rendering).

## HTMX Support

### HTMX Attributes

HTMX attributes (`hx-post`, `hx-get`, `hx-target`, `hx-swap`, etc.) are written as plain literal attributes. There is no special DSL wrapper because HTMX is already declarative:

```
button hx-post="/posts/#{post.id}/like" hx-target="#like-count" hx-swap="innerHTML" "Like"

form hx-post="/posts" hx-target="#post-list" hx-swap="afterbegin"
  input type="text" name="title" placeholder="Title"
  textarea name="body" placeholder="Body"
  button type="submit" "Create Post"

div#like-count
  = post.likes_count

a hx-get="/posts?page=2" hx-target="#post-list" hx-swap="innerHTML" "Load more"
```

### HTMX Delivery

HTMX is embedded in the Doot binary itself and served automatically (gzipped) from a built-in path. There is:

- No CDN dependency
- No npm install
- No version for the user to manage
- No script tag the user needs to add (it is included automatically by the base layout system)

The user should ideally not be aware a JavaScript library is involved. HTMX is "how interactivity works" in Doot. It is served from the same binary that serves the application.

## `style-embed` Directive

The `style-embed` directive embeds a CSS file inline in the `<head>`:

```
head
  title= block title || "My App"
  style-embed "app.css"
```

This reads `static/app.css` and embeds its content in a `<style>` tag. It avoids an extra HTTP request for the stylesheet and ensures styles are available immediately on page load.

```html
<head>
  <title>My App</title>
  <style>/* contents of static/app.css */</style>
</head>
```

## Auto-Escaping

All expression output is HTML-escaped by default. This means:

| Character | Escaped to |
|-----------|-----------|
| `<` | `&lt;` |
| `>` | `&gt;` |
| `&` | `&amp;` |
| `"` | `&quot;` |
| `'` | `&#x27;` |

### When Escaping Applies

- `= expression` output is always escaped
- String interpolation in text (`"Hello, #{name}"`) is escaped
- String interpolation in attributes is escaped

### Overriding Auto-Escape

Use `!=` for raw (unescaped) output:

```
div!= post.rendered_html
```

This is an explicit opt-in. It should only be used when you know the content is safe (e.g., pre-sanitized HTML or content generated by trusted code).

## Error Pages

### Automatic Error Page Rendering

If `views/errors/404.do` exists, it is rendered when a 404 occurs (e.g., when `db.posts.find(id)` returns nil). If `views/errors/500.do` exists, it is rendered on unhandled server errors.

If these files do not exist, a default styled error page is rendered. No configuration is needed either way.

### Example Error Pages

```
# views/errors/404.do
extends "layouts/base"

block title
  "Page Not Found"

block content
  div.error-page
    h1 "404"
    p "The page you are looking for does not exist."
    a href="/" "Go back home"
```

```
# views/errors/500.do
extends "layouts/base"

block title
  "Server Error"

block content
  div.error-page
    h1 "500"
    p "Something went wrong. Please try again later."
    a href="/" "Go back home"
```

## Complete Example

A full layout and page template showing most features:

### Layout

```
# views/layouts/base.do
doctype html
html
  head
    title= block title || "My Blog"
    meta charset="utf-8"
    meta name="viewport" content="width=device-width, initial-scale=1"
    block head
    style-embed "app.css"
  body
    nav.main-nav
      div.container
        a.logo href="/" "My Blog"
        div.nav-links
          a href="/posts" "Posts"
          if ctx.current_user
            a href="/posts/new" "New Post"
            a href="/logout" "Logout"
          else
            a href="/login" "Login"
            a href="/signup" "Sign Up"
    main.container
      block content
    footer.site-footer
      div.container
        p "Built with Doot"
```

### Page Template

```
# views/posts/show.do
extends "layouts/base"

block title
  = post.title

block head
  meta name="description" content="#{post.body.truncate(160)}"

block content
  article.post
    header.post-header
      h1.post-title= post.title
      div.post-meta
        span "by #{post.author_name}"
        span.separator "|"
        span= format_date(post.created_at)

    div.post-body!= post.rendered_html

    if ctx.current_user
      div.post-actions
        a href="/posts/#{post.id}/edit" "Edit"
        button hx-delete="/posts/#{post.id}" hx-confirm="Delete this post?" "Delete"

  section.comments
    h2 "Comments (#{comments.count})"

    if comments.empty?
      p.no-comments "No comments yet. Be the first!"
    else
      each comment in comments
        div.comment
          p.comment-body= comment.body
          span.comment-meta "#{comment.author_name} - #{time_ago(comment.created_at)}"

    if ctx.current_user
      partial "comments/form", post: post
```

### Partial

```
# views/comments/_form.do
form.comment-form method="post" action="/posts/#{post.id}/comments" hx-post="/posts/#{post.id}/comments" hx-target=".comments" hx-swap="beforeend"
  textarea name="body" placeholder="Write a comment..." required="" rows="3"
  button.btn type="submit" "Post Comment"
```

This example demonstrates: inheritance with multiple blocks, class shorthand, HTMX attributes, conditionals, iteration, partials with locals, expression output, string interpolation, and auto-escaping.
